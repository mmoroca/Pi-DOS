Verified:
- Every original advertised timing is retained (including preferred timing).
- Base EDID, audio, HDMI capabilities and existing CTA DTD are byte-identical.
- Only 72 previously empty bytes at 0xad..0xf4 and CTA checksum 0xff changed.
- Base checksum 0x8f and CTA checksum 0xba both validate.
- Exactly four unique timings added; no new edid-decode conformity failures.

Added modelines (normal progressive scan, no hardware doublescan):
  640x400_70 25.180 640 656 752 800 400 412 414 449 -HSync +VSync
  640x350_70 25.180 640 656 752 800 350 387 389 449 +HSync -VSync
  720x348_70 28.320 720 738 846 900 348 386 388 449 +HSync -VSync
  640x350_60 25.200 640 656 752 800 350 413 415 525 +HSync -VSync

The nominal 25.175 MHz VGA clock is rounded to 25.180 MHz because EDID
DTD pixel clocks have 10 kHz precision. This gives 70.100223 Hz. The
720x348 adaptation uses 70.081663 Hz / 31.466667 kHz and is custom VGA
scan timing for a Hercules-sized image, not original 50 Hz Hercules timing.

The custom 640x350 at 60 Hz mode uses a 25.200 MHz clock and a normal
800x525 progressive raster: exactly 60.000000 Hz and 31.500000 kHz.
Its larger vertical blanking interval keeps horizontal sync within the
advertised 31-60 kHz range. The front porch is capped at the EDID DTD
limit of 63 lines; physical CRT picture geometry still needs checking.

Recreate from the project root:
  python3 tools/image/create-crt-edid.py dac-original.bin dac-crt.bin

Image integration: the build installs dac-crt.bin into the embedded initramfs
as /lib/firmware/edid/dac-crt.bin. BOOT/cmdline.txt enables it for both ports:
  drm.edid_firmware=HDMI-A-1:edid/dac-crt.bin,HDMI-A-2:edid/dac-crt.bin
The file cannot simply be placed next to cmdline.txt on the BOOT partition.
The existing video=HDMI-A-1:720x400@70 boot request can remain.

Limitations:
The source identifies itself as NEC LCD1530V and already contains invalid
or inconsistent metadata. Those fields are deliberately preserved. The
full conformance check still reports the original failures below; this is
not a claim of strict EDID conformity or physical DAC/CRT validation.
See docs/buildroot-pi5.md for image build and BOOT update instructions.
Physical display lock and mode switching still require hardware validation.
EDID availability alone does not guarantee DOSBox-X selects each new mode.
